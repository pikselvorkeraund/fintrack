# AGENTS.md — правила разработки FinTrack

## Сборка и проверка

- **Локальная сборка и запуск тестов запрещены.** Билд и проверка ошибок выполняются **только на GitHub** после загрузки (push) — через CI/CD workflow.
- Перед коммитом **тщательно проверяй все связи и качество кода вручную**: сверяй сигнатуры DAO ↔ Repository ↔ ViewModel ↔ Screen, удаляй устаревшие вызовы, проверяй импорты и замыкание скобок после правок.
- Не используй `execute_command` для `gradlew`/`build`/`test` — это не пройдёт локально и не является способом проверки.

## Данные и БД (Room + SQLCipher)

- БД зашифрована (SQLCipher), открывается только после ввода графического ключа через `DbHolder`. Не обходи `DbHolder` и не создавай прямые экземпляры `AppDatabase`.
- Любое изменение схемы — **миграция Room** с корректным заполнением новых таблиц из существующих данных (см. `AppDatabase.MIGRATION_1_2`). `fallbackToDestructiveMigration()` допускается только как аварийная страховка, но миграция обязательна.
- Все операции, затрагивающие несколько таблиц (например, `transactions` + `stats`), выполняются в одной транзакции через `db().withTransaction { }`.

## Вывод записей

- **Список записей показывается только для активной валюты** (фильтр `WHERE currencyCode = :cur`).
- **Пагинация — keyset по id**, по 20 записей на страницу: `WHERE (:lastId = 0 OR id < :lastId) ORDER BY id DESC LIMIT :limit`. Запрос должен идти по PK-индексу и **не сканировать всю таблицу** — это требование производительности.
- **Ленивая загрузка**: следующая страница подтягивается при прокрутке `LazyColumn` к концу (за несколько элементов до низа), от последнего загруженного id.
- После добавления новой записи активной валюты — вставка в начало окна без перечитывания БД; после удаления — изъятие из окна с дозагрузкой до полного окна.

## Статистика (суммы)

- **Отдельная таблица `stats`** с инкрементальными суммами. Суммы **не пересчитываются полным сканом транзакций**.
- Вклад каждой транзакции прибавляется/вычитается дельтой при **каждом добавлении/удалении** её валюты.
- Статистика ведётся **по каждой валюте и каждому периоду**: `TOTAL`, `DAY`, `WEEK`, `MONTH`, `YEAR` (см. `PeriodType`).
- Итоговые доход/расход на дашборде читаются из строки `TOTAL` соответствующей валюты — точечный запрос по PK.

## UI / UX

- **Удаление записей — только через простое подтверждение** (`AlertDialog` с категорией и суммой), без мгновенного удаления.
- Все новые строки интерфейса добавляй **в оба языка** (`StringsEn` и `StringsRu` в `AppLocale.kt`), через `LocalStrings`.
- Ошибки БД не должны ронять процесс — показывай пустой/безопасное состояние.

## Язык и стиль

- Комментарии и пользовательские сообщения — на русском в `StringsRu`, на английском в `StringsEn`.
- Соблюдай существующие паттерны проекта: Hilt-инъекции, `StateFlow` во ViewModel, Compose Material3.
